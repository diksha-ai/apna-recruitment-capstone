# Apna Recruitment Decision Intelligence (synthetic data)

All data are synthetic (generated by `generate_data.py`); nothing reflects Apna's real records. No protected attribute is used or inferred.

## How to run

```
git clone <https://github.com/diksha-ai/apna-recruitment-capstone.git> && cd <apna-recruitment-capstone>
pip install -r requirements.txt
python generate_data.py     # prints: 800 10 170 0537bc7fb4a044719831c43166e79d3c
python part1.py
python part2.py
python part3.py
python part4.py             # reads outputs/part2_results.txt for knn_best_k, so run after part2.py
```
`common.py` is a shared helper (importing it runs nothing). Every file in `outputs/` is regenerated by these commands.

## Part 1 findings

**R1.1** H0 (mean 8.0 days) is rejected: z_stat = 2.8930, beyond the critical value 1.96 (mean_value = 8.9382, 95% interval 8.3026 to 9.5738). A Type I error here would mean concluding the true average time to an offer decision differs from 8 days when the planning assumption is in fact right. The gap is 0.9382 days (under one day, about 12% above plan): statistically clear, but practically modest; it matters mainly if capacity plans are tight or multiplied over many hires.

**R1.2** n_required = 1293 against 800 rows available. The current sample gives a margin of about 0.64 days (1.96 × se_value), not 0.5, so the team would need roughly 490 more records to reach half-a-day precision.

**R1.3** gd_slope_gap = 0.0000 (below 0.001): the squared-error cost of a one-predictor line has a single minimum and, on a standardised predictor, 500 steps of η = 0.1 reach it (cost is already identical at 100 and 500 updates), so gradient descent lands on the closed-form line.

**R1.4** resid_sd_ratio_raw = 3.7525 and resid_sd_ratio_log = 1.0396. The raw model shows a strong funnel (residual spread grows with the fitted value: 2.3155 in the lower half vs 8.6891 in the upper half); the log-log model removes it (0.5165 vs 0.5369).

**R1.5** Predictors with |coefficient| > 0.05 (mechanical rule, not an importance ranking): ln(X4) expected salary (1.1576), X2 interview reschedules (0.0940), X3 salary gap ratio (0.1067) and X6 competing offer (0.1518). mr_adj_r2 = 0.7403 vs loglog_adj_r2 = 0.6561: the extra predictors earn their place, since adjusted R² rises clearly even after the penalty for seven predictors.

## Part 2 findings

**R2.1** Lowest to highest after 200 updates: η = 1.0 (0.3703) < η = 0.1 (0.3776) < η = 0.01 (0.5091). A too-small rate is still far from the minimum after 200 steps; a larger rate got there fastest here (it did not diverge on this standardised, smooth problem, though a large rate can overshoot in general).

**R2.2** Largest absolute weights: X3 salary gap ratio (0.9013), X1 experience (−0.5554) and X2 reschedules (0.5505). The largest odds ratio is 2.4629 for X3: each one-SD rise in the pay gap multiplies the odds that the candidate declines by about 2.5, other predictors fixed.

**R2.3** blind_accuracy = 0.7875 versus 0.8042 at τ = 0.5: predicting "nobody declines" is almost as accurate, so accuracy hides the failure to find declines. Lowering τ from 0.5 to 0.3 raised recall from 0.4706 to 0.7451 and lowered precision from 0.5455 to 0.4634.

**R2.4** Logistic at τ = 0.3 has f1 = 0.5714 and recall = 0.7451; KNN (K = 5) has f1 = 0.3696 and recall = 0.3333. Logistic is clearly better.

**R2.5** I would deploy the logistic model at τ = 0.15, the training-cost-optimal threshold (cost_tau). On test rows it costs INR 6050 (cost_test_at_tau), against INR 11800 at τ = 0.5 and INR 20400 if nobody is flagged. The threshold was chosen on training rows so that the test rows stay an untouched, honest check rather than being tuned to.

## Part 3 findings

**R3.1** WCSS drops: 2→3 = 659.8282, 3→4 = 108.0739, 4→5 = 171.0575, 5→6 = 45.5466. The elbow supports K = 3 (elbow_k = 3: the 3→4 drop is under half the 2→3 drop). The drops do not shrink steadily (4→5 exceeds 3→4), so the pinned starting rows give a reproducible solution, not necessarily the global optimum.

**R3.2** (from `part3_segments.csv`)
- **A, "Settled, low-friction candidates"** (322 records; experience 47.5 months, pay gap 0.225, outcome_rate 0.0186, 3.6 days): keep to a light-touch, fast offer process.
- **B, "Busy, slow-moving schedulers"** (255; 6.07 reschedules, expected pay 28.7 thousand INR, outcome_rate 0.2353, 17.1 days): offer fixed interview slots and a single point of contact to cut reschedules and days to decision.
- **C, "Early-career with a wide pay gap"** (223; 14.4 months, gap 0.712, completeness 38.5, outcome_rate 0.4664): the highest outcome_rate. Start the pay-gap conversation and recruiter follow-up before the offer is sent.

**R3.3** Single linkage, cut with 4 clusters: {E2, E3, E6}, {E1}, {E4}, {E5}. Complete linkage, cut with 2 clusters: {E1, E4, E5} and {E2, E3, E6}. Single linkage joins on the nearest pair, so chains form and every merge height stays at or below 3.4, making the biggest gap the early 1.4 jump; complete linkage uses the farthest pair, so the last merge sits at 7.9, a huge gap after 2.9.

**R3.4** The standardised means are zero (step 1), so centring changes nothing. PC1 (52.27% of variance) contrasts X1 experience (+0.5317) and X5 profile completeness (+0.4418) against X3 pay gap (−0.5187), X2 reschedules (−0.4100) and X4 expected salary (−0.2916). Three components keep at least 80% (cumulative 0.7593 for two, 0.8616 for three). Mean PC1 scores are A = 1.7773, B = −0.7831, C = −1.6709: PC1 orders the segments from experienced/complete profiles to early-career/wide-gap ones, with B in between.

## Part 4 findings

**R4.1** S4 (X1 ≤ 24 months) is best by both measures (info gain 0.1252, Gini gain 0.0606) because it makes the purest children: 45.7% positives on the yes side (86 of 188) against 8.9% on the no side (33 of 372). A tree grown until every leaf is pure memorises noise in 560 rows and generalises worse; a maximum depth or a minimum number of records per leaf stops it.

**R4.2** I would ship the logistic model (f1 = 0.5714, recall = 0.7451 at τ = 0.3). Stump: f1 0.5532, recall 0.7647; KNN: 0.3696, 0.3333; hard_vote: 0.5344, 0.6863; soft_vote: 0.5507, 0.7451. Combining did not help: no ensemble beat the logistic model on f1.

**R4.3** The two misclassified points (3 and 7) carry a total normalised weight of 0.5000 after round 1. Round 2 trusts h2 more because its weighted error is lower (0.1667 vs 0.2500), giving alpha 0.8047 vs 0.5493.

A convolution layer on 128×128×3 needs 1792 parameters (conv_layer_params) versus 50332672 for the fully connected layer (fc_layer_params), because filters are shared across positions.

Model B: W_xh is 128×64, W_hh is 128×128, W_hy is 16×128 (rnn_total = 26768). rnn_total does not grow with sequence length because the same weights are reused at every time step.

For 10 classes: ReLU in hidden layers, softmax output with categorical cross-entropy loss. In a very deep plain network, backpropagation multiplies many factors below 1, so gradients shrink towards the early layers and they barely learn; a skip connection adds an identity path (output = input + transformation) so gradients flow straight back.

## Model-choice memo

**To:** Head, Talent-Acquisition Operations

**Recommendation:** put the logistic-regression model into production and flag candidates whose predicted decline probability is at least 0.15.

On 240 held-out records (51 declines), logistic at 0.3 reached recall 0.7451 and F1 0.5714, ahead of KNN (recall 0.3333, F1 0.3696) and of hard and soft voting (F1 0.5344 and 0.5507). The one-question stump (experience of 24 months or less) is close (F1 0.5532) but adds nothing.

**Cost:** a follow-up costs INR 50 and a missed decline INR 400. The cheapest threshold on training data was 0.15. On the test records the logistic model then costs INR 6050, versus INR 11800 at the default 0.5 and INR 20400 if nobody is flagged. I did not compute these costs for the other models, so none is claimed.

**Risk:** only 51 positive test records and a single split, so the INR figures could move noticeably on other data; the data are synthetic and the unit costs are rough. Expect many extra follow-ups with candidates who would have accepted.

Neither Model A nor Model B is worth building before this model is in production; both are small to size but have no demonstrated value yet.

## Limitations

1. The data are synthetic, generated from known formulas, so real-world performance, costs and drift are untested.
2. A single stratified split with only 51 positive test records: the best K (5), the threshold (0.15), and every test cost are valid for this split only and noisy.
3. K-means uses pinned starting rows that give a reproducible but not necessarily globally optimal solution, and the 6-cohort dissimilarity table is tiny, so the dendrogram cuts are fragile.
4. The z-test uses the normal approximation on a right-skewed days column, and the INR 50 / INR 400 costs are rough assumptions, not measured values.
5. Models like these must never be used to rank people on protected attributes, and none is in the data.
